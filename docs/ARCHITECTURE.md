# Pheonix architecture

Vanilla JS ES modules, CesiumJS for the globe, Three.js for branding only, Vite for the build. There is no UI framework.
Server code runs as Vite dev and preview middleware (see `vite.config.js`). The only separate process is the optional
local voice service in `server/voice/`.

## Layout

```
index.html            page shell: #globe, #ui, #splash, favicon and manifest links
vite.config.js        plugins: cesium and the server proxies (cctv, aircraft, traffic, transit, bikes), /voice proxy
src/main.js           entry point: global styles, then boot()
src/app/              startup and wiring (see below)
src/config.js         shared constants: imagery, terrain and geocoder URLs, the world view
src/core/             createBus(), the event bus every module shares
src/globe/            the Cesium viewer and everything that moves its camera, plus place search
src/ui/               createShell(): the glass chrome (zoom buttons, Data menu, voice mount, toast)
src/cameras/          camera catalog, clustering, markers, field of view cones, createCameraLayer
src/player/           floating camera players and their stream adapters
src/layers/           optional data layers (aircraft, traffic, transit, bikes, labels), one folder each
src/voice/            browser side of the voice assistant
src/brand/            splash, 3D phoenix, 3D globe mark
src/styles/           design tokens, glass surface, and one css file per component
public/brand/         logo and icon files, generated by scripts/brand/build.mjs
server/providers/     data adapters behind the proxies (cameras, aircraft, traffic, transit, bikes)
server/voice/         local speech to text, text to speech and wake word
```

## Startup (`src/app/`)

`boot.js` runs the steps in a fixed order: splash, globe, shell, cameras and players, data layers, actions,
then the splash is dismissed and the voice assistant starts. Splash, logo and voice are optional. If one fails
to load, the app still runs (`optional.js`). If the globe itself cannot start, `errorScreen.js` shows a reload card.

- `layerState.js` decides which layers are on at start (all of them, unless the user chose otherwise) and
  remembers the choice in localStorage under `pheonix.layers`.
- `placeFlight.js` turns a geocoder result into a camera move: whole country for big places, a close look for cities.
- `actions/` is the set of commands the voice assistant can call. Each file is a factory and `actions/index.js`
  merges them into one object:
  - `navigation.js`: `flyToPlace`, `zoom`, `worldView`
  - `cameras.js`: `showCamerasNear`, `openNearestCamera`, `randomCamera`, `nextNearest`, `nextCamera`, `closeAllCameras`
  - `aircraft.js`: `followAircraft`, `stopFollowing`
  - `layers.js`: `showLayerIn`, `setLayer`
  - `cameraProbe.js` is the helper that checks a still camera really returns a frame before it is opened.

The finished app is also exposed as `window.pheonix` (globe, cameras, players, layers, actions, bus, assistant) for debugging.

## Globe (`src/globe/`)

Public exports from `index.js`: `createGlobe` and `searchPlaces`.

- `createViewer.js` builds the Cesium viewer with Esri imagery (OpenStreetMap as fallback) and terrain.
- `cameraControls.js` has `getView`, `flyTo`, `flyToRect`, `zoomBy`, `worldView` and the opening shot.
- `wheelZoom.js` handles wheel and trackpad zoom around the cursor. A layer can take over the wheel with `setWheelOverride`.
- `keepAlive.js` keeps frames coming while the user drags or zooms, because rendering is on demand.
- `moveEvents.js` gives `onMoveEnd(fn)`, a debounced "the camera stopped" signal.
- `search.js` is `searchPlaces(query)`: OpenStreetMap Nominatim, keyless, one request a second, cached.

`createGlobe(container)` returns `{ viewer, Cesium, flyTo, flyToRect, getView, onMoveEnd, zoomBy, worldView, setWheelOverride, destroy }`.

## Module contracts

- `createBus()` returns `{ on(type, fn), emit(type, detail) }`. `on` returns an unsubscribe function.
- `createShell(root, { onZoom, onWorld, onLayer, onBrand })` returns `{ voiceMount, brandMount, toast(msg), setLayers(list), setLayerPressed(id, on) }`.
- `createCameraLayer({ viewer, bus })` returns the camera API (`nearest`, `randomNear`, `nextNearest`, `highlight` and more).
  It emits `camera:select` `{ camera }` when a marker is clicked.
- `createPlayerManager({ container, bus })` returns `{ open(camera), close(id), closeAll(), count(), openNext() }`.
  Status labels are real: LIVE, SNAPSHOT, OFFLINE, UNAVAILABLE.
- `loadLayers({ globe, bus })` finds `src/layers/<name>/index.js` files, each with a `descriptor` and a `create`.
  See `docs/LAYERS.md`.

Bus events: `camera:select`, `camera:highlight`, `cameras:error`, `layer:status`, `view:moved`, `voice:state`, `player:count`.

## Styles

`tokens.css` (colors, sizes), `glass.css` (the glass surface and buttons) and `base.css` (page, globe and #ui) load from `main.js`.
Each component imports its own css: `styles/ui/*.css` from `ui/shell.js`, `styles/app/errorScreen.css` from `app/errorScreen.js`,
and the layer, camera, player and voice styles from their own folders.

## Rules

- Camera video connects only when a player opens, never one connection per marker.
- Never fake liveness. Status comes from the real stream or probe result.
- No emoji icons, SVG and CSS only. Respect `prefers-reduced-motion` and `backdrop-filter` support (`@supports`).
- Keep third-party license and attribution notices (Cesium, imagery credits, camera provider `credit` strings).
